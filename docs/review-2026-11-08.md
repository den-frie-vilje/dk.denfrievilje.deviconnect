## Release judgement (scope D)

**The branch's unconditional two-step should not ship as a fix.** Its premise, a clamp
"back in 03.50", is marked unverified in its own commit (ff0843a) and none of the four units
runs 03.50. MEASURED today: the two-step works on 03.48 and 03.49 alike, and `main`'s gate
(`main:69-76`, workaround below 03.49 and whenever the version is unknown) already applies
it on the 03.48 unit, which is the only firmware where the clamp has been observed. The
unconditional form costs every 03.49+ user a 3 s wait in each sub-15 °C set (Flow actions
and the UI wait on the listener) and an intermediate 15 °C setpoint report, visible as a
flicker and possibly a relay change. That is a behaviour change without an observed need;
keep the gate until a 03.50 unit shows the clamp. If simplicity is preferred regardless, the
unconditional form is safe to ship on today's evidence, but the comment at :66-70 must lose
the 03.50 claim and the changelog must not call it a fix. This is a judgement call (taste);
the rest below is not.

**A clean-up release (1.2.3) is warranted**, because #1 and #2 are bugs on `main`, Live
today: a setting that does nothing and writes whose rejection the user never sees. Ordered
by value over risk:

1. Check write statuses (#1): a few lines, no hardware dependency, turns silent failures
   into the reverted UI value the code already promises. Bug.
2. Resolve the calibration setting (#2): remove it from the InControl manifest and
   `onSettings`, changelog "Removed"; or keep it and reject in `onSettings` once support is
   known. Bug.
3. Remove the diagnostics (#3) and the three unimplemented attributes from the limit read
   (#10); keep the one-frame read. Bug if shipped.
4. Mark `measure_power` approximated and stop removing it when `load_watts` is 0 (#6).
   Guideline; low risk.
5. Move the two-step into an async `setParser` (#5) so the double listener goes away.
   Medium risk, needs one hardware pass on a 03.48 unit; the status check from step 1 then
   lives inside the library's retry.
6. Tame init and announce traffic (#4): drop `getOnOnline`, read the two standard thermostat
   attributes once in `runMaintenance`, let polling depend on report age (#9). Medium risk,
   hardware pass with the repair flow.
7. Trivia: description and README wording (#8), `sourceMap` (#13), de-duplicate or ignore
   `interview.json` (#12), grouped changelog (#14), spread `super.ATTRIBUTES` (#15).

Leave for a later minor release, with hardware verification: sub-capability Flow cards and
gentler sensor removal (#7), schedule state from 0x0025, warnings from the Diagnostics
cluster. The uncommitted edits on this branch are session instrumentation and should not be
merged; the one-frame limit read and the branch's comment on the knob range are the only
parts worth carrying over.
